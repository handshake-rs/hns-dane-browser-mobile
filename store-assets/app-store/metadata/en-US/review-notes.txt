No sign-in is required. Shakescape has no developer-operated account, subscription, in-app purchase, advertising, analytics, custodial service, or exchange service. It does include a native, noncustodial HNS wallet. A user can create or restore a wallet, synchronize public chain activity, receive HNS, scan a Handshake payment QR code, and review and approve an HNS send. Websites cannot access or invoke the wallet, and the unfinished Bitcoin, name-operation, and Shakedex marketplace screens are not exposed in this release.

Shakescape uses WKWebView for rendering and an authenticated loopback proxy at 127.0.0.1 for app traffic. It does not install a VPN or change the device's system proxy.

This build registers the HTTP and HTTPS schemes and uses Apple's managed default-browser entitlement. When selected as the default browser, it navigates directly to the system-supplied destination through the same address field, strict navigation classifier, and WKWebView path used for in-app navigation. It does not claim Universal Links for specific domains. This build does not include the separate Browser App Installation entitlement and does not handle MarketplaceKit installation requests.

Ordinary web test:
1. Launch the app. When "Enter an address to begin" appears, enter https://shakescape.com/ and tap Go.
2. Confirm the page loads and the security label shows the selected ICANN validation path.

Handshake test:
1. Enter https://shakescape/ and tap Go.
2. The bundled Handshake header snapshot allows proof-backed resolution while foreground header synchronization continues.
3. Confirm the security label identifies the HNS resolver and DANE validation path.
4. Open Settings to inspect HNS resolution, synchronization, resolver trace, proof details, privacy policy, and source code.

Native wallet test:
1. Open Settings, then Handshake wallet.
2. A fresh install reports that no wallet exists. Creating or restoring a wallet is optional for browser review. If Create is exercised, record the one-time recovery phrase only in a reviewer-controlled secure location and confirm it.
3. Unlock may take longer on older devices while device-protected signing authority is prepared. During that operation the controls remain disabled and show progress.
4. The unlocked wallet can synchronize directly with Handshake peers, show balance and recent activity, produce a receive address and QR code, and prepare a guarded HNS send. Every send displays a native review and requires explicit approval. No website can open that approval.
5. The camera permission is requested only after tapping the scanner in the native send form. The QR image and decoded Handshake address are processed on the device and are not uploaded.
6. An unlocked wallet can be deleted after two destructive confirmations that identify the network/account and require typing DELETE. This removes the device-bound key before encrypted database files; it does not remove a recovery phrase saved elsewhere.

Network note: some review networks block Handshake peer traffic or direct authoritative DNS. Experimental P2P DNS relay consumption is off by default. Recursive HNS DoH recovery is also blank by default. Answers obtained through an enabled recovery path still require local HNS proof, DNSSEC, TLSA, and DANE validation. If no permitted validated path succeeds, the request fails closed.

Cleartext HTTP pages are marked insecure. No reviewer-supplied personal data or credentials are needed.
